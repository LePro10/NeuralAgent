# Claude view

- Daemon: `crates/na-daemon/src/claude_view.rs` (parser, tail, prompt/activity/mode detection from the vt100 screen, commands/skills, `@` files, uploads, transcribe). Wire types: `crates/na-protocol/src/claude.rs`. Client: `packages/protocol/src/{cv.ts,client.ts}`.
- UI: `packages/app/src/components/claude/**`, `KeyBar.tsx`, toggle in `Pane.tsx`; choice stored per device (`useUi.claudeView`).
- Images: paste, drop, picker, clipboard-read button; upload via `Upload` request; terminal pane (`TerminalView.tsx`) uploads and types the path. Tauri: `platform.onFileDrop` (local paths, typed directly).
- Terminal scaling (Goal 3): `refit(force)` re-reports the size on visibilitychange, focus, resize, pageshow, visualViewport, font ready, DPR change, intersection and snapshot reset. The old size cache skipped the resize when another client had changed the shared PTY.
- Android paste: on AVD na36 the WebView paste event (KEYCODE_PASTE into a textarea) delivers the image as a File, so normal paste works. A WebView cannot read the clipboard by itself, so `NativePlugin.readClipboardImage` (ClipboardManager + content URI, 12 MB cap) backs the paste buttons and the empty-paste fallback, and a `ViewCompat` receive-content listener on the Bridge WebView forwards keyboard-inserted images (Gboard) as a `paste` plugin event, which the web side re-emits as `na-paste-image`. The listener and a real Gboard chip were not exercised; signing the app in on the emulator was not done, so the Android path ends at "native read returns the PNG" and "paste event carries a File".
- Desktop: `clipboard_image` Tauri command (arboard + png) is the fallback when the paste event has no file and no text; `onFileDrop` feeds terminal and composer. Not run in a real Tauri window (compiles; JS typechecks).
- Transcript noise: "No response requested." is hidden, interrupted tool calls read "Interrupted by user" in muted style.
- Verified in Chromium: dictation (fake mic wav, Parakeet) fills the composer; image paste uploads and inserts the host path, also through the relay (web remote, phone size). Headless WebKit hangs on the current web build before the host list (the original `web-remote.mjs` does too), so the scaling check used Chromium: resize events and tab back resend the PTY size, only the focused pane reclaims.
- Not verified: real Gboard chip, Tauri window, WebKit remote.

## Claude-style rebuild (UI)
- Look: tokens in `packages/ui/ui/styles/claude.css` (the `/* Claude view */` file, imported by `packages/app/src/styles/app.css`): `*-cv-*` colours on top of `--claude-*`, warm light and dark, sizes that grow on phones (`[data-mode=phone]`), serif `Source Serif 4` (OFL, `@fontsource-variable/source-serif-4`). Components use only these tokens.
- Files: `ClaudeView.tsx` (layout, 768px column, greeting, activity, dock), `Transcript.tsx` (turns, user bubbles, thinking, copy row / long-press action sheet), `tools.tsx` (tool rows, groups "Read 3 files ›", diffs), `Markdown.tsx` (serif prose, tables, code blocks with copy), `PromptCard.tsx` (permission/question card), `Composer.tsx`, `Picker.tsx` (phone: ui `Sheet` re-dressed by `.cv-sheet`; desktop: a popover above the composer, kept to its width), `Spark.tsx`, `models.ts` (models, 5 efforts, 6 modes in Claude's words).
- Picker is a deliberate exception to "no custom overlays" (design-system.md): Claude's pickers need title + description + check rows and must open upward from the composer on desktop. The "Copied" toast lives in the dock for the same reason.
- Permission card: `asPermission()` maps "Yes" → Allow once, "Yes, and …" → Always allow (or the CLI's own words, e.g. "Switch to auto mode"), "No" → Deny; anything else is a numbered question card. Esc closes, the terminal icon opens the live menu. The pending tool call (newest tool_use without result) gives verb, file and diff; otherwise the daemon's title is parsed (`parseTitle`).
- Mode picker: the CLI only cycles (Shift+Tab), so the composer steps until `meta.mode` matches and says so when a mode is not offered (bypass/don't ask need start flags).
- Daemon: `detect_mode` knows "manual mode on" and "don't ask on"; prompt titles keep the dashed command/diff box between ``` lines; the statusline hook's `effort.level` feeds `meta.effort` (the "◐ medium · /effort" hint is only shown now and then).
- Checked with screenshots (`research-local/polish/cv-shots/`, driver in `/tmp/na-cv-scratch/drv.mjs`) at 390×844, 360×780, 390×450 (keyboard) and 1440×900, light and dark: transcript, permission card (Bash and Edit), model/effort/+/mode pickers, slash list.
- Open: real iOS/Android keyboard (only emulated by viewport height), the tab bar stays under the composer in the 450px case (AppShell), attachment upload has no byte progress (the `upload` request is one shot; tiles show waiting/uploading/error).

## Images in the conversation (D50)
- Daemon: `crates/na-daemon/src/cv_image.rs` (`images_in` numbering, `image_ref`, header `dims`, `serve`/`fit` with downscale). `claude_view.rs` puts `CvImage` refs on `ToolResult.images` and `Image.image`; "[image]" stays only for images without base64 bytes.
- Client: `packages/app/src/lib/cvImages.ts` (cache, sizes, names; tested), `components/claude/Images.tsx` (`Thumb`, `Pictures`, viewer). Tool rows show a large thumbnail under the row (a bare image `Read` has no chevron), a closed "Read 2 files" group shows small thumbnails, user bubbles show tiles.
- Viewer: pinch / wheel / double tap zoom, drag pan, swipe down (touch) or Esc / click beside closes, arrows between pictures, Copy (as PNG), Save (not on Android).
- Check: `scripts/dev/scenes/claude-images.mjs` (fake transcript, needs `CLAUDE_CONFIG_DIR` for daemon and shot). Shots in `research-local/polish/img-shots/`. Not exercised: real pinch/swipe on a device, Save in the Tauri window, the remote 1600 px path end to end (covered by the Rust test).
